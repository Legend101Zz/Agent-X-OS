The workflow contract user → orchestrator → child

user role

created_by = you · no parent

Your big asks. Drop on the board via natural language or hermes kanban --board agent-x-os create --triage. The orchestrator picks it up and decomposes.

"do X"
   ↓
hermes kanban create \
  --title "TASK: do X"

orchestrator role

agentx-orchestrator profile

Decomposes user tasks into N children. Routes each child to the best-fit subagent. Validates each child's handoff and decides: approve, rework, or reassign. Closes the root when all children are done, then triggers status regeneration.

comment + edit body + unblock
   ↓ (rework)
hermes kanban reassign \
  --reclaim (wrong engine)

child role

has a parent · assigned to a subagent

One unit of work. The orchestrator decides which subagent handles it. Children can be todo (waiting on parent or schedule), ready, in_progress, blocked, or done.

kanban_complete(
  summary=...,
  metadata={files, tests, ...}
)

Lifecycle end to end

you: "do X"
  ↓
[TRIAGE] → auto-decomposer fires (~60s)
  ↓
[USER card · todo · assignee=default]   ← root, awaits decomposition
  ↓
[CHILD 1] [CHILD 2] ... [CHILD N]   ← orchestrator creates, each with parent=root
  ↓
parent = in_progress → children auto-promote todo → ready
  ↓
[CHILD x · in_progress] → worker spawns → kanban_complete or kanban_block
  ↓
orchestrator validates each child
  ├─ APPROVED → done → next sibling auto-promotes → eventually all done → root auto-promotes
  ├─ REWORK  → orchestrator: comment + edit body + unblock → worker respawns
  └─ REASSIGN → orchestrator: reassign to different subagent (wrong engine picked)
  ↓
[USER card · ready] → orchestrator picks it up → marks done with summary
  ↓
[STATUS card] → agentx-status regenerates AGENTX_STATUS_.html
  ↓

Session-limit handoff (when a worker hits any cap)

If a child card blocks with context / cost / runtime / turns / rate-limit / oauth-credits-exhausted, the orchestrator does not unblock-and-retry. It runs the 4-step handoff:

1. Inspect:  git log on worktree branch → list what's already committed
2. Decide:   pick a handoff target — same engine at lower effort, or different engine (codex ↔ claude)
3. Create:   new CHILD card inheriting the same branch, body lists DONE vs NOT DONE, references the old card id
4. Reclaim:  reclaim the blocked worker, archive the old card, the new worker continues from last clean commit

OAuth routing means most session-limit handoffs just lower the effort level (e.g. xhigh → high) or pick a cheaper alias on the same engine — no dollar cost, just lower-quality output.
